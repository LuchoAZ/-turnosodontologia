3. MCP
------------------------------------------------------------------------------
Servidor elegido: context7 (remoto, https://mcp.context7.com/mcp)
Tipo: remote | enabled: true | sin credenciales obligatorias
Configuración: sección mcp.context7 de ~/.config/opencode/opencode.json
  (reproducida sin secretos en README.md, sección 5.4)

Por qué context7 y no Playwright MCP:
  C-02 se define por SQL de PostgreSQL (RLS, políticas, set_config) y por el
  manejo de la sesión en SQLAlchemy. context7 aporta documentación oficial
  directa a ese trabajo; Playwright MCP recién se vuelve útil con la UI de
  agenda (C-07) y agrega herramientas que hoy no se usan.

Uso real:
  - resolve-library-id("PostgreSQL", "RLS multi-tenant") -> /websites/postgresql
  - resolve-library-id("SQLAlchemy", "SET LOCAL RLS")   -> /sqlalchemy/sqlalchemy
  - query-docs: CREATE POLICY / ENABLE ROW LEVEL SECURITY
  - query-docs: SET LOCAL vs set_config por transacción
  - query-docs: EXCLUDE USING gist (preparación de C-06)

Corrección concreta:
  Antes: SET LOCAL app.current_tenant = :tenant_id
         (SET no acepta parámetros bindeados; interpolar el UUID es riesgoso)
  Después: SELECT set_config('app.current_tenant', :tenant_id, true)
           (parameterizado y transaction-local)
  Archivo: backend/app/db/tenant_context.py
  Test: test_el_contexto_de_tenant_no_se_filtra_entre_transacciones_del_pool

4. AISLAMIENTO MULTI-TENANT (GATE RN-TEN-02)
------------------------------------------------------------------------------
- membership y price_concept tienen RLS habilitada y FORZADA (FORCE ROW LEVEL
  SECURITY).
- Políticas basadas en NULLIF(current_setting('app.current_tenant', true), '')
  ::uuid. El NULLIF evita el cast de cadena vacía tras un commit y mantiene el
  comportamiento fail-closed.
- Rol odontologia_app: NOLOGIN NOSUPERUSER NOBYPASSRLS.
- Los tests hacen SET ROLE odontologia_app antes de consultar: un superusuario
  ignora RLS y, sin ese SET ROLE, el verde sería falso.
- Prueba de mutación: el mismo SELECT como owner ve filas de A y de B; como rol
  de app ve solo A. Demuestra que el filtro lo hace la política, no un WHERE
  accidental.
- Test de reversibilidad: upgrade head -> downgrade base -> upgrade head.
